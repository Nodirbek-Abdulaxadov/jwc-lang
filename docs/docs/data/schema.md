# Schema

A `table` is a Postgres table. There is no mapping layer, no annotations
and no second description of the same thing — the declaration *is* the
DDL, and `jwc migrate new` writes it out.

```jwc
namespace db.notes;

database App : Postgres;
schema notes of App;

table Notes of App.notes {
    id         bigint primary key identity;
    org_id     bigint;
    title      varchar(200);
    body       text;
    published  boolean default false;
    created_at timestamptz default now();

    index on (org_id, created_at);
}
```

## The three declarations

| | What it is |
|---|---|
| `database App : Postgres` | a **connection**, named `App` so schemas can be qualified. The database name is never declared — it comes from `DATABASE_URL`. |
| `schema notes of App` | a Postgres schema. `CREATE SCHEMA notes`. |
| `table Notes of App.notes` | a table in it. `notes.notes` in DDL. |

`App.` exists to make source references unambiguous and stops at the
source: `App.billing.Invoices` is `billing.invoices` in SQL, never
`app_billing.invoices`.

## Columns

The type is the Postgres type, spelled as Postgres spells it: `bigint`,
`int`, `smallint`, `numeric(14, 2)`, `varchar(255)`, `text`, `boolean`,
`timestamptz`, `date`, `time`, `interval`, `uuid`, `jsonb`, `inet`,
`bytea`.

A `?` suffix makes the column nullable. Without it the column is
`NOT NULL`, which is the default because most columns are.

```jwc no-compile
region     varchar(20)?;         -- NULL allowed
created_at timestamptz default now();
```

### Modifiers

| Modifier | Effect |
|---|---|
| `primary key` | on the column, or `primary key (a, b)` as a table-level clause for a composite |
| `identity` | `GENERATED BY DEFAULT AS IDENTITY` |
| `unique` | a single-column unique constraint |
| `default <expr>` | a column default |
| `private` | the column can never appear in a projection — not even by asking |
| `server` | the column is written by the server, never by a request body |
| `as "name"` | the **physical** name, when it differs from the declared one |

`private` is worth dwelling on. A password digest declared `private` is
not a column a `select ... as { … }` can name: the checker rejects the
projection. It is not a convention, and it does not depend on every
future projection remembering to leave it out.

## Constraints carry their message

```jwc no-compile
email varchar(255) unique : "bu email allaqachon ro'yxatdan o'tgan";

unique (org_id, slug) : "bu tashkilotda bunday slug bor";

check (amount > 0) : "summa musbat bo'lishi kerak";
```

The sentence after the `:` is what the client sees when the constraint is
violated — a `409` for a unique violation, a `400` for a check. It travels
with the constraint, so the endpoint does not need a read-then-insert to
produce a friendly message, and the race that read opens does not exist.

A constraint with no message stays a fault: a 500, because it means
something the author did not anticipate.

## Foreign keys

```jwc no-compile
foreign key (org_id) references App.org.Orgs (id) on delete cascade;
foreign key (actor_id) references App.auth.Accounts (id) on delete set null;
```

`on delete cascade` is the database doing the cleanup. Writing the cascade
by hand in a transaction — load the children, delete them, delete the
parent — is what a schema without foreign keys forces, and it is slower
and easier to get wrong.

## Indexes

```jwc no-compile
index on (org_id, created_at);
unique index on (lower(email));
```

`jwc lint --constraints` reads the queries and reports a `where` or an
`orderby` with no index behind it.

## Keeping the names a database already has

`as "…"` overrides the physical name, on a table or on a column:

```jwc no-compile
table Accounts of App.auth as "tbl_user_accounts" {
    id         bigint primary key identity;
    created_at timestamptz as "createdAt";
}
```

This is what a port off an older schema reaches for first. The declared
name is what source and projections use — and therefore what the JSON
response carries — while the physical name is what the database keeps.

## What the schema becomes

```bash
jwc migrate new init .       # writes the up/down pair and a snapshot
jwc migrate up .             # applies what is pending
jwc migrate verify .         # every constraint and index, by name
```

`jwc migrate verify` is the one that catches drift: it compares the
constraint and index names the binary expects against the ones the
database holds, and names each mismatch.
