# Project structure

A JWC project is `<name>.jwcproj` (manifest) plus one or more `.jwc` source files in the same directory or a subtree. `jwc` walks **up** from `cwd` to find the manifest; no environment variable to set.

## Minimum layout

```
hello/
├── hello.jwcproj
└── main.jwc
```

`main.jwc` is conventional — `jwc run` looks for a `main()` function across **every** `.jwc` file in the project, so name them however you like.

## Realistic layout

```
my-api/
├── my-api.jwcproj            # manifest
├── jwcproj.lock              # resolved deps (gitignore optional, recommended commit)
├── main.jwc                  # main() + serve(8080)
├── routes/
│   ├── users.jwc             # route GET "/users" ...
│   └── posts.jwc
├── models/
│   ├── User.jwc              # entity User { ... }
│   └── Post.jwc
├── middleware/
│   └── auth.jwc              # middleware Auth { ... }
├── migrations/               # generated by `jwc migrate new ...`
│   ├── 20260101_120000_init.up.sql
│   └── 20260101_120000_init.down.sql
└── bin/                      # `jwc build` output (gitignore)
    └── debug/
        └── my-api.exe
```

There is **no module system**. Every `.jwc` file in the tree contributes to one flat namespace, so a parse error in any file fails the whole load. Routes / functions / entities can reference each other across files freely.

## Manifest cheat-sheet

```jsonc
{
  "name": "my-api",
  "version": "0.1.0",
  "type": "app",                 // "app" (default, runnable) or "pkg" (library)
  "dependencies": {
    "logger": "^0.1.0",          // semver from the registry
    "local-lib": { "path": "../local-lib" },
    "auth-mw":   { "git": "https://github.com/me/auth-mw", "rev": "main" }
  }
}
```

Full reference: [Manifest](../packages/manifest).

## What's auto-ignored

`jwc fmt`, `jwc publish`, and the example-fixture harness skip these directories: `.git/`, `.jwc-build/`, `target/`, `node_modules/`, `bin/`, `.vscode/`, `.idea/`. Don't put source there.
