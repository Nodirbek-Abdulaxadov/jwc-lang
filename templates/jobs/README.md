# {{name}}

Background-queue scaffold generated by `jwc new {{name}} --template jobs`.

## Run

```bash
jwc run                            # in-memory queue (lost on restart)
JWC_QUEUE_DRIVER=postgres jwc run  # durable queue, requires Postgres
```

## Endpoints

| Method | Path           | Description                              |
|--------|----------------|------------------------------------------|
| POST   | `/send-email`  | Enqueues `process_email` and returns 202 |
| GET    | `/health`      | Liveness probe                           |

Test it:

```bash
curl -X POST http://localhost:8080/send-email \
     -H 'content-type: application/json' \
     -d '{"to":"a@b.com","subject":"hi"}'
```

You should see `processing email job` in the server log a moment later.

## Extend

- Add another job: drop `src/ReportJob.jwc` with
  `function build_report(payload) { ... }`, register it in `main()` via
  `register_job_handler("build_report", build_report)`, then enqueue
  from any route with `enqueue("build_report", json_stringify(...))`.
- Switch to durable: set `JWC_QUEUE_DRIVER=postgres` and provide a
  Postgres connection. Run `jwc migrate up` once — the queue manages
  its own table.
- Need it now? Use `enqueue_urgent(...)` to jump the queue.
